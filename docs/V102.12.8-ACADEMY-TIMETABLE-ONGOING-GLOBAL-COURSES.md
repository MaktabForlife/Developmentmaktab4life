# V102.12.8 — Academy timetable pills + Ongoing Global Courses

## Purpose

This release addresses the Academy Home timetable presentation review and adds an interim way to represent a continuously running Global Course without inventing Start/End dates before the V104 generic Program Builder exists.

## Academy timetable hierarchy

Detailed session pills receive more horizontal space than generic/rolled-up pills. The compact pill remains useful for a staff overview, while the detailed pill carries the user-facing academic information.

For a participant/student, a label-only Program roll-up is not rendered when that participant already has an applicable detailed Program session for the same Program and start time. This removes the duplicate-pill case without removing richer staff views.

## Global Course pill content

A Global Course/run name is an admin/internal scheduling identifier and is not part of the Academy Home pill.

DETAIL delivery for a Global Course contains the Global Subject title plus optional Module and Teacher fields. The Account UI renders:

`Global Subject`

`Module · Teacher` (only the values that exist)

If the teacher is TBA/unassigned, no teacher-detail label is added. TBA remains valid in scheduling/publication data.

## Ongoing course representation

No new schema column is added. An ongoing GlobalSubjectRuns record is represented by:

- `StartDate = ""`
- `EndDate = ""`
- `Active = TRUE`

The API additionally maps this to `ongoing: true`. Active ongoing courses resolve as `CURRENT`.

A fixed course remains a record with both valid StartDate and EndDate.

Partial dates are invalid: one blank and one populated date is neither a valid fixed course nor a valid ongoing course.

## Weekly generation window

A weekly recurrence cannot be expanded infinitely. For an ongoing course, session generation therefore requires temporary generation bounds when a weekly row is submitted:

- `generationStartDate`
- `generationEndDate`

These are request-only scheduling controls and are not written into GlobalSubjectRuns. They simply determine which exact `GlobalTimetableSessions` dates are created in that batch.

Once created, an ongoing session may be edited to any valid date because the course itself has no date boundary.

## Fixed-course safeguards

For a fixed course, session dates must remain within StartDate/EndDate and existing sessions still prevent course boundaries from being shrunk across them.

## Schema and roadmap

No migration. Keep `PlatformConfig!B3 = 102.0.8` and 19 required Platform tabs.

The ongoing Global Course mode is an interim V102 facility. It does not replace the roadmap:
