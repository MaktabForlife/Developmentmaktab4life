# V102.6.2 menu, PIN and role-label corrections

V102.6.2 is a development correction release applied over V102.6.1.

## Restricted menu controls

V102.6.1 correctly assigned the `hidden` class and `aria-hidden="true"` to
restricted Admin Home tiles, but the later-loaded Home tile component declared
`display: grid` with equal specificity. The later declaration won the cascade,
so the controls remained visible.

V102.6.2 adds a component-specific terminal rule that makes either hidden state
`display: none !important`. Restricted controls are therefore absent from the
visual and keyboard layout. The desktop grid also sizes itself to the number of
visible controls.

For SENIOR and TEACHER the Admin Home controls are:

- Home
- Admin Home
- Resources

The main Admin navigation entry is intentionally retained because it is the
authorized path to Resources. Backend authorization remains authoritative.

## Incorrect-PIN retry

When `/account/<uniqueid>` rejects a PIN, the login field is cleared. Controls
are re-enabled and focus is returned to the PIN field before the next attempt.
The account page no longer requires a reload after an incorrect PIN. Existing
rate limiting and authentication validation are unchanged.

## Senior Teacher display label

The user-facing name for `SENIOR` is now `SENIOR TEACHER` in the account page,
Profile and AdminRecords management UI.

This is a display-only change. Continue storing and submitting `SENIOR` in:

- `AdminRecords`
- `UserCourseAccess`
- account and workspace tokens
- API request and authorization values

No Sheet migration or manual role edit is required.

## Migration boundary

V102.6.2 changes no Sheet tab, header or record. `PlatformConfig!B3` remains
`102.0.4`; `PlatformConfig!B4` must not change. Do not rerun central account
migration. No Apps Script, Worker variable, binding or secret changes are
required. The approved browser-session authentication policy remains deferred.
