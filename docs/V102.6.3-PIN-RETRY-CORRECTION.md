# V102.6.3 PIN retry correction

V102.6.3 is a development correction release applied over V102.6.2.

## Cause

The account page disabled the login form before awaiting the PIN authentication
request. After that asynchronous wait, it read `event.currentTarget` again when
trying to re-enable the form. A DOM event's `currentTarget` is only reliable
while the event listener is actively handling the event, so the later reference
could be unavailable.

The error handler still cleared the PIN, but the disabled input could not accept
the next attempt.

## Correction

The submitted form element is now captured before the asynchronous request and
the same stable reference is used to disable and re-enable its controls. After a
rejected PIN:

1. The error is displayed.
2. The PIN field is cleared.
3. The form controls are re-enabled.
4. Focus returns to the PIN field.

The user can enter the correct PIN without reloading. The same stable-reference
handling is applied to first-PIN setup API failures.

## Boundaries

The correction changes no authentication validation, token lifetime, login rate
limiter, role permission or Sheet data. V102.6.2 menu visibility and the
display-only `SENIOR TEACHER` label remain unchanged.

`PlatformConfig!B3` remains `102.0.4`; B4 must not change. No migration, Apps
Script change, Worker setting, binding or secret is required.
