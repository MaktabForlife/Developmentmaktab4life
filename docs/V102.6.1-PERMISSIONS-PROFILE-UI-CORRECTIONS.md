# V102.6.1 permissions, Profile and Global Curriculum UI corrections

V102.6.1 is a development correction release applied over V102.6.

## Course resource permissions

| Role | Add course resources | Modify existing resources |
| --- | --- | --- |
| GLOBAL_ADMIN in course context | Yes | Yes |
| ADMIN | Yes | Yes |
| SENIOR | Yes | No |
| TEACHER | Yes | No |
| STUDENT | No | No |

The Worker enforces these rules. Menu visibility is only the user-interface
reflection of the backend authorization boundary. Every successful resource
creation retains the existing course audit requirements.

## Student Records

Student Records are ADMIN-only. SENIOR and TEACHER have no Student Records
menu tile and do not gain access by calling a route directly. Teacher progress,
attendance and operational views remain restricted to the teacher's assigned
class scope.

## Menu visibility

Admin Home hides controls for capabilities the active course role does not
have. SENIOR and TEACHER retain the Resources control because they can add
resources. ADMIN-only controls remain hidden from them.

## Profile

The app menu contains one Profile control. The Profile card displays the
account name, authorised courses and roles, and the current context. Course and
role switching is started inside this card; the former separate duplicate
menu item is removed.

Every switch continues to use the central account screen, revalidate the
selected context and issue a new course/role-scoped token without another PIN.

## Global Curriculum layout and validation summary

All five Global Curriculum controls are rendered as visible tab buttons:
Subjects, Modules, Tasks, Resources and Subscriptions. The inherited global
full-width button rule no longer makes every tab occupy an entire horizontal
viewport or makes small `New` controls fill their panel.

Platform validation now reports the global subject count separately from the
global-subject subscription count. Zero subscriptions is valid when no direct
subject-access rows have been created.

## Schema and authentication boundary

V102.6.1 changes no Sheet tab or header. `PlatformConfig!B3` remains
`102.0.4`; deployment does not change `PlatformConfig!B4`.

The approved all-user authentication storage policy remains deferred and is
not activated by this correction release.
