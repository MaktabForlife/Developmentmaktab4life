# ﷽ V102.11.1 Platform Sheet migration

V102.11.1 keeps the V102.11 Global Course timetable tables and adds one lifecycle table for cancelled/rescheduled session history. It also moves the fixed scheduling timezone into central Platform configuration.

## Before the code deployment

Keep `PlatformConfig!B3` (`PlatformSchemaVersion`) at `102.0.6` while preparing the Sheet.

Back up the Platform Sheet first.

### 1. Create `GlobalTimetableSessionLifecycle`

Create a new Platform Sheet tab named exactly:

`GlobalTimetableSessionLifecycle`

Paste these exact headers into `A1:L1`:

| Cell | Header |
|---|---|
| A1 | SessionLifecycleID |
| B1 | SessionID |
| C1 | PublicationID |
| D1 | Status |
| E1 | RescheduledFromSessionID |
| F1 | RescheduledToSessionID |
| G1 | CreatedDate |
| H1 | CreatedByAccountID |
| I1 | CreatedByAccountName |
| J1 | ModifiedByAccountID |
| K1 | ModifiedByAccountName |
| L1 | ModifiedDate |

Leave row 2 onward blank. Existing V102.11 sessions and publications need no seed rows: when no lifecycle row exists they are interpreted as `SCHEDULED`.

Lifecycle values written by V102.11.1 are:

- `SCHEDULED`
- `CANCELLED`
- `RESCHEDULED`

Current working lifecycle rows have blank `PublicationID`. Publication writes immutable lifecycle snapshot rows containing the publication ID.

### 2. Add the fixed Platform timezone

In `PlatformConfig`, use the first completely empty data row and enter:

| Column | Value |
|---|---|
| A — ConfigKey | `PlatformTimezone` |
| B — ConfigValue | `Africa/Johannesburg` |
| C — UpdatedDate | blank is acceptable for migration |
| D — UpdatedByAccountID | blank is acceptable for migration |
| E — UpdatedByAccountName | blank is acceptable for migration |

There must be exactly one `PlatformTimezone` row. Do not create a duplicate if it already exists.

Do **not** change `PlatformSchemaVersion` yet.

## Deploy V102.11.1

1. Commit the V102.11.1 changed files to development GitHub.
2. Allow Cloudflare Pages and the Worker to deploy from the **same commit**.
3. Confirm the Worker root response reports `version: "102.11.1"`.
4. Confirm the account page shows `V102.11.1`.
5. Only after both frontend and Worker are live, change `PlatformConfig!B3` from `102.0.6` to `102.0.7`.
6. Run Platform validation.

Expected validation after cut-over:

- Platform schema `102.0.7`
- **18 required tabs**
- exactly one `PlatformTimezone`
- `GlobalTimetableSessionLifecycle` present with the exact header row
- existing V102.11 publications remain valid even when no lifecycle rows existed before the migration

## Focused checks

After validation:

1. Open **Global Curriculum → Course Scheduler**.
2. Confirm the header refresh icon reloads newly created/modified courses without logout/login.
3. Create or edit a DEVELOPMENT course with one timetable row left as Teacher `TBA`; saving/generating must work.
4. Confirm publication is blocked until every scheduled session has a teacher.
5. Publish a course.
6. Confirm published course editing is locked until **Revise timetable** is selected.
7. Open a revision, mark one occurrence `CANCELLED`, and reschedule another occurrence.
8. Publish the revision.
9. Confirm the original published snapshot remains unchanged and the new publication contains the cancelled/rescheduled lifecycle states.
10. Confirm **Global Access** shows subject names on header row 1 and `PAID`/`FREE` on header row 2. FREE subjects must show the FREE token and retain the saved entitlement tick.
11. Confirm **Program Timetables** still opens and existing Program timetable functionality is unchanged.

## Rollback

If V102.11.1 must be rolled back:

1. Change `PlatformConfig!B3` back to `102.0.6` **before** reverting code.
2. Revert Pages and Worker together to the same V102.11 commit.
3. Leave `GlobalTimetableSessionLifecycle` in place; V102.11 ignores the additive tab.
4. Leave `PlatformTimezone` in `PlatformConfig`; V102.11 ignores the additive key.
5. Do not delete existing V102.11 timetable/publication rows.

This rollback does not require reconstructing or editing V102.11 publication history.
