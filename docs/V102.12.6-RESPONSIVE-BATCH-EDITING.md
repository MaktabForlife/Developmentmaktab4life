# V102.12.6 — Responsive Batch Editing

## Purpose

This release consolidates the V102.12.5 review corrections without changing the Platform Sheet schema.

## Session editing model

The Course Scheduler keeps changes in browser draft state until the section Save action is pressed. The request body contains only changed sessions. The Worker reads the timetable once, stages all requested changes, validates the complete proposed timetable (including overlaps and course/date constraints), and only then issues one Google Sheets `values:batchUpdate` request.

Existing sessions are historical records. The UI therefore does not delete them: a cancelled occurrence is retained with lifecycle status `CANCELLED`. A date/time edit updates the same SessionID. The legacy reschedule endpoint remains available for backwards compatibility but is not part of the V102.12.6 editor.

## Academic Calendar editing model

Terms, Islamic Dates and Holidays use independent browser draft sets and one Save action per section. The batch endpoint validates every requested change before writing. Generated South African Holidays continue to use override/suppression rows internally where required; there is still no Sheet migration.

Islamic Dates remain reference/informational dates. `AcademyCalendar` retains its legacy Sheet columns, but Islamic API objects omit `alternateDate` and `teachingImpact` in V102.12.6.

## Responsive UI

Global Curriculum and Academic Calendar no longer depend on fixed wide page layouts. Wide tables/cards reflow at tablet/mobile breakpoints, while the Global Access matrix retains contained horizontal scrolling because it is intrinsically matrix-shaped. Save icons use the existing shared `/icons/save.svg` icon system and transparent Attendance-style action treatment.
