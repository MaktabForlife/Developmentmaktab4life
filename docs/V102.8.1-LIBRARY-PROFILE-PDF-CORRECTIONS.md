# V102.8.1 Library, Profile and PDF corrections

## Scope

V102.8.1 is a focused correction over deployed V102.8. It does not begin the
timetable integrator and does not change the Platform or course Sheet schemas.

## Global Subjects Profile context

For an ordinary active account, `buildAvailableContexts` now appends one
`GLOBAL/STUDENT` context whenever the account has at least one active
`UserGlobalSubjectAccess` row whose referenced global subject is active. This
applies whether or not the account also has course memberships.

The Profile card therefore shows, for example:

- Reboot Your Maktab — STUDENT — Current
- Global Subjects — STUDENT — Switch

The Profile does not list individual subscribed subjects. Individual subjects
remain inside the Global Subjects Library. Selecting the single Profile context
calls the existing central switch endpoint, revalidates the entitlement, issues
a new token and opens the restricted Global Library workspace without another
PIN.

Automatic login is unchanged: a course membership remains the automatic
context when course access exists. A global-only subscriber still opens the
Global Subjects workspace automatically.

## Library source pill

The Library continues to expose these filters in this order:

1. All
2. each authorised active course in `CourseRegistry` row order
3. Global Subjects when active subscriptions exist

They are rendered together as one segmented pill. Desktop and tablet layouts
use one row. Compact layouts wrap within the same control so every option is
visible without a dropdown or horizontal scrolling. Choosing a segment filters
the displayed Library only; it does not switch operational course or role.

## Student split PDF access

The existing PDF split implementation is reused for Students. No duplicate PDF
viewer or permission model is introduced.

- The split control is shown only at widths of 1024px or more.
- It is shown only when the authorised current Library catalogue contains at
  least two PDFs.
- Each PDF is resolved through its own existing protected access request.
- A Student may compare any two PDFs visible through the currently selected
  Library source, including authorised course/global combinations from All.
- This grants view access only. It does not grant upload, create, modify or
  delete rights.
- Mobile and narrow layouts continue to use the normal single-PDF viewer.

## PDF header placement

The `n/total` PDF shelf selector now sits immediately to the left of the PDF
title. Previous and Next remain in the navigation group to the right, followed
by the role-appropriate PDF actions.

## Security and data boundary

- Platform schema remains `102.0.4`.
- No Sheet tab, header, migration or data row is added.
- Account migration must not be rerun.
- No Worker variable, secret, binding or Apps Script deployment changes.
- Global Subjects access still requires an active account, active subscription
  and active global subject.
- Course and resource authorisation remain fail-closed and are not inferred
  from the displayed menu, URL, CourseID or resource link.
- Current browser-session persistence is unchanged; the approved authentication
  policy remains deferred and documented separately.
- Production V101.1 remains untouched pending the final production merge plan.
