# V102.12 — Academy timetable delivery contract

## Purpose

V102.12 is the read/delivery layer between the two independent scheduling systems and the central-account Home page.

```text
Program Timetables ───────────────┐
                                  ├─> Academy timetable API ─> Academy Home
Published Global Courses ─────────┘
```

The builders remain independent. V102.12 does not copy a Global Course into a Program Sheet and does not copy Program sessions into the Platform Sheet.

## Authoritative sources

### Programs

For each active `CourseRegistry` row, V102.12 reads that Program's current `SystemConfig.TimetableLiveSource`:

- `PUBLISHED_TIMETABLE` → the current immutable Program publication snapshot.
- otherwise → the existing live `TeacherAssign` timetable source.

This preserves the Program's already-configured live-source decision.

### Global Courses

Only the current publication referenced by `GlobalTimetableRunState.CurrentPublicationID` is delivered. Draft/DEVELOPMENT Global Course sessions never appear on Academy Home.

## Backend visibility contract

Every Academy event is normalised by the Worker before it is returned.

Common fields:

```text
kind: PROGRAM | GLOBAL
visibilityLevel: DETAIL | LABEL
relevant: true | false
canOpenZoom: true | false
status
date
startTime
endTime
title
```

`eventKey` is an ephemeral Academy response key (`AE0001`, etc.) and is not an underlying database/session identifier.

### Program DETAIL

May include:

- Program name
- subject
- module
- group
- teacher display name
- Zoom link only when `canOpenZoom = true`

### Program LABEL

Includes only:

- Program name
- date/time
- generic status/response metadata

It does **not** include subject/module/group/teacher/Zoom or operational IDs.

### Global DETAIL

May include:

- Global Subject name
- Global Course/run display name
- module
- teacher display name
- current publication lifecycle status
- Zoom link only when `canOpenZoom = true`

### Global LABEL

Includes only:

- Global Subject label
- date/time
- generic status/response metadata

It does **not** include Global Course/run name, module, teacher, Zoom or operational IDs.

## Program access validation

Central `UserCourseAccess` is not sufficient by itself to expose DETAIL.

Before granting Program DETAIL, V102.12 validates the membership against the Program Sheet:

- STUDENT → exactly one `StudentRecords.StudentID = CourseRecordID`, matching central `UniqueID`, local Active = TRUE.
- ADMIN/SENIOR/TEACHER → exactly one `AdminRecords.AdminID = CourseRecordID`, matching central `UniqueID`, matching role, local Active = TRUE.

If the local identity no longer matches, that Program is treated as unauthorised for detail and only LABEL data is returned.

## Program visibility

| Viewer | Returned view |
|---|---|
| Matching-group student | DETAIL for own group + `ALL` |
| Student viewing another group | LABEL |
| Student ClassGroup `0` | DETAIL across groups |
| Program Teacher | DETAIL across authorised Program |
| Teacher's own session | DETAIL, relevant, Zoom allowed |
| Another teacher's session | DETAIL, muted/not relevant, no Zoom |
| Program ADMIN/SENIOR | DETAIL across authorised Program |
| GLOBAL_ADMIN | DETAIL across Programs |
| Active account without membership | LABEL |

Program timetable row `GroupNo = 0` does not mean `ALL` for an ordinary student.

## Global Course visibility

| Viewer | Returned view |
|---|---|
| Active account, FREE subject | DETAIL |
| Current paid subscriber | DETAIL |
| Assigned Global Course teacher | DETAIL |
| GLOBAL_ADMIN | DETAIL |
| Active non-subscriber, PAID subject | LABEL |

FREE/PAID entitlement is still determined by V102.10 policy + matrix rules; no duplicate entitlement system is introduced.

## Lifecycle delivery

- `SCHEDULED` → normal current occurrence; Zoom may be allowed.
- `CANCELLED` → remains visible as cancelled; no active Zoom.
- `RESCHEDULED` source → remains visible as rescheduled; no active Zoom.
- linked replacement → delivered as its own scheduled occurrence.

Published snapshots remain immutable.

## Time and week rules

- Academy Home uses `PlatformTimezone`.
- Week boundaries are Monday–Sunday.
- Program weekly timetable rows are mapped onto exact dates in the selected week.
- Global Course sessions already contain exact dates.
- Browser display is consistently `13h00`.

## Failure isolation

If one active Program's Sheet/timetable source is temporarily unavailable, V102.12 does not expose partial private data and does not discard the rest of the Academy timetable. The response omits that Program's sessions and returns a generic, non-sensitive warning naming the Program.

## Schema and rollback

V102.12 requires no Sheet migration:

- Platform schema remains `102.0.7`.
- Required Platform tabs remain 18.
- rollback is code-only to V102.11.2.
