# V101.4.3 Timetable publication migration

V101.4.3 replaces the multi-lesson dialog with one Subject, one optional Module,
multiple Days, and either `ALL` or multiple individual Groups. Every selected
individual group receives its own required Teacher and optional Zoom override.
One save creates `days × groups` audited `TimetableSessions` rows.

## Required Sheet changes

Back up the workbook, then add these three tabs with the exact names and header
rows. Do not add data rows manually.

### TimetableCourseState — A1:I1

`CourseID, Stage, CurrentPublicationID, CreatedDate, CreatedByAdminID, CreatedByAdminName, ModifiedByAdminID, ModifiedByAdminName, ModifiedDate`

`Stage` is `DEVELOPMENT` or `PUBLISHED`. A missing course-state row is treated as
`DEVELOPMENT`; the Worker creates it on the first timetable write or publish.
`CurrentPublicationID` is retained when published data returns to development,
so draft edits never mutate or replace the last immutable snapshot.

### TimetablePublications — A1:G1

`PublicationID, CourseID, VersionNo, PublishedDate, PublishedByAdminID, PublishedByAdminName, SessionCount`

Each publish appends one immutable, course-specific version record.

### PublishedTimetableSessions — A1:N1

`PublishedSessionID, PublicationID, SourceSessionID, CourseID, TimeSlotID, DayOfWeek, SubjectID, ModuleID, GroupNo, TeacherID, ZoomLink, PublishedDate, PublishedByAdminID, PublishedByAdminName`

Each publish copies every active draft session for the course into a new,
immutable snapshot. Historical snapshot rows must not be edited or deleted.

## Existing tabs

`Courses`, `TimeSlots`, and `TimetableSessions` retain the V101.4 headers.
`AdminAuditLog` retains the V101.3 A:I headers. The three new tabs are required;
the builder fails closed if a tab or exact header row is missing.

## Deletion lifecycle

- A never-published session may be permanently deleted only while its course is
  in `DEVELOPMENT`. The row deletion and `HARD_DELETE` audit event are submitted
  in one Google Sheets batch request.
- A session that appears in any published snapshot can never be hard-deleted.
  Delete makes its draft row inactive and records `DEACTIVATE`.
- Inactive sessions can be displayed and restored after conflict validation.
- Publishing includes active draft rows only.

Session and publication IDs use UUID-based values so hard deletion cannot cause
an ID to be reused. Existing sequential session IDs remain valid.

## Deployment order

1. Back up the production Google Sheet.
2. Add the three tabs and exact headers above using the supplied CSV templates.
3. Confirm the V101.3 `AdminAuditLog` header remains exact.
4. Deploy the V101.4.3 Worker.
5. Deploy the V101.4.3 frontend.
6. Open Admin > Timetable Builder, verify each course shows Development, create
   or review sessions, and publish the first snapshot.

## Live-source boundary

V101.4.3 creates and manages builder publication snapshots, but student and
teacher timetable reads continue to use `TeacherAssign`. This release does not
silently cut the live timetable over to `PublishedTimetableSessions`.
