# V102.5 subscription access schema

## Purpose

V102.5 establishes the central access model for subscriptions without
duplicating course membership and without connecting subscription eligibility
to timetables.

- A Student subscription to a course is the existing active
  `UserCourseAccess` row with `Role=STUDENT`.
- Staff course roles remain in `UserCourseAccess` with `ADMIN`, `SENIOR` or
  `TEACHER`.
- Direct access to a central global subject is stored separately in
  `UserGlobalSubjectAccess`.
- Resources belonging to standalone global curriculum are stored centrally in
  `GlobalResources`.
- There is no general `UserSubscriptions` tab.

Roles determine what a person may do. Access rows determine which course or
global subject the person may enter. Billing, payment and renewal records are
not authorization records and are not introduced in this release.

## Platform schema version

The required Platform schema becomes `102.0.4` and contains ten required tabs:

1. `CourseRegistry`
2. `UserAccounts`
3. `UserCourseAccess`
4. `UserGlobalSubjectAccess`
5. `GlobalSubjectList`
6. `GlobalModuleList`
7. `GlobalTaskList`
8. `GlobalResources`
9. `PlatformConfig`
10. `PlatformAuditLog`

`TeacherScheduleIndex` is removed from the required contract because
subscriptions have no timetable limits, overlap rules or cross-course schedule
checks. The existing live tab may remain during V102.5 rollback verification;
the Worker no longer reads or validates it.

## Exact new headers

Create `UserGlobalSubjectAccess` and place this header in `A1:J1`:

```text
SubjectAccessID,AccountID,SubjectID,Active,CreatedDate,CreatedByAccountID,CreatedByAccountName,ModifiedByAccountID,ModifiedByAccountName,ModifiedDate
```

Create `GlobalResources` and place this header in `A1:P1`:

```text
ResourceID,SubjectID,ModuleID,TaskID,ResourceName,ResourceType,ResourceFormat,ResourceDescription,ResourceLink,Active,CreatedDate,CreatedByAccountID,CreatedByAccountName,ModifiedByAccountID,ModifiedByAccountName,ModifiedDate
```

Do not add data rows during installation. The exact headers are also supplied
as CSV templates.

## Access rules

### Course subscriptions

`UserCourseAccess` remains authoritative. Do not copy Student course access
into another subscription table.

An effective course Student subscription requires:

- active `UserAccounts` account;
- active `UserCourseAccess` row;
- `Role=STUDENT`;
- active registered course;
- valid course-local `CourseRecordID` linked to the Student record.

The existing V102.4 revalidation and dynamic course routing remain unchanged.

### Global-subject subscriptions

`UserGlobalSubjectAccess` is unique by `AccountID + SubjectID`. Each row uses a
UUID `SubjectAccessID` and references an existing central account and an
existing `GlobalSubjectList.SubjectID`.

Effective learner access will require all three records to be active:

- `UserAccounts`;
- `UserGlobalSubjectAccess`;
- `GlobalSubjectList`.

V102.5 validates this contract but does not yet add a global-subject learner
screen or make a global-subject-only account an operational login context.

## Global resources

A global subject can be purchased without a course. Its resources therefore
cannot depend on a course Sheet or course Library. `GlobalResources` stores
metadata for resources belonging to central global subjects, modules and
tasks.

Allowed `ResourceType` values are:

```text
EBOOK, PRINTABLE, AUDIO, VIDEO, OTHER
```

The Worker validates that every global resource:

- has a unique ResourceID;
- references an existing global subject;
- uses a module belonging to that subject when ModuleID is present;
- uses a task belonging to the same curriculum branch when TaskID is present;
- has a name, supported type and link.

Course-specific resources remain in their course Sheets and course Libraries.
V102.5 does not copy existing course resources into `GlobalResources` and does
not yet provide global-resource management or learner-delivery endpoints.

## No timetable subscription rules

There is no limit on how many courses or global subjects an account may access.
The platform does not block subscriptions because of:

- timetable overlaps;
- simultaneous courses;
- teacher schedule overlaps;
- course combinations;
- time-slot availability.

Timetables remain course-local operational information. They are not part of
subscription authorization.

## Safe upgrade from V102.4

This upgrade is for development only. Production remains stable at V101.1 and
must receive a separate, rehearsed merge package after the V102 development
programme is complete.

1. Back up the Platform Sheet and V102.4 source.
2. Create the two new empty tabs with the exact headers while
   `PlatformSchemaVersion` remains `102.0.3`.
3. Deploy the V102.5 Worker. Account authentication temporarily accepts both
   `102.0.3` and `102.0.4` so this step does not interrupt login.
4. Change `PlatformConfig!B3` from `102.0.3` to `102.0.4`.
5. Run **Validate Platform Sheet** and resolve every error.
6. Deploy the complete V102.5 Pages frontend.

Do not rerun central account migration. Do not populate either new tab during
the upgrade. Do not delete the live `TeacherScheduleIndex` tab during this
release's rollback period.

## Deferred implementation

Later releases may add:

- Admin UI for global curriculum, direct subject access and global resources;
- global-subject-only account navigation;
- merging subscribed global curriculum into the learner experience;
- payment-provider plans, renewals and billing references;
- central provisioning when new course students are registered.

Payment status may activate or deactivate an access row later, but application
authorization must continue using the access row rather than trusting a
browser, URL, payment callback or timetable.
