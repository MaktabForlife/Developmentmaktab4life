# V102.8 unified multi-course and global Library

## Purpose

V102.8 integrates authorised course Libraries and subscribed global subjects
behind the application's existing single **Library** navigation item.

The Library source selector is:

1. **All** — every authorised active course Library plus subscribed active
   global subjects.
2. One entry for each authorised active course, in `CourseRegistry` row order.
3. **Global Subjects** — active global content for the account's active direct
   subscriptions.

Selecting a Library source changes only the displayed catalogue. It does not
change the account's operational course or role.

## Profile switching

The application Profile card is the only course/role switch control. Each
non-current context is selectable directly. The Worker rereads the central
account and access records, issues a new context-scoped token, clears
course-specific client caches and opens the corresponding workspace without
requesting another PIN.

`SENIOR` remains the stored role and displays as `SENIOR TEACHER`.

## Authorisation model

The browser never chooses a SpreadsheetID. `/api/library/catalogue` uses the
credential-bound central token to:

1. revalidate the active `UserAccounts` row;
2. revalidate the token's current course membership or global entitlement;
3. enumerate active authorised courses from `UserCourseAccess` and
   `CourseRegistry`;
4. resolve the matching course-local `StudentRecords` or `AdminRecords`
   identity separately in each course Sheet;
5. apply that course's student-group restriction when reading its resources;
6. merge only active global subjects permitted by active
   `UserGlobalSubjectAccess` rows.

GLOBAL_ADMIN may read every active registered course Library. Other accounts
receive only active courses for which they have a valid central membership.
Spreadsheet IDs are not returned to the browser.

## Global-only subscriptions

An account with no course membership and at least one active global-subject
subscription receives a `GLOBAL/STUDENT` context. It opens the Student Library
workspace directly with course operational menus hidden. The token is bound to
an exact active `UserGlobalSubjectAccess` row and its active global subject.

## Protected files

Course resources continue through the existing protected course Drive access
route. Cross-course access first revalidates the requested CourseID against the
central account, resolves that course's local identity and then applies the
existing active-resource, group and Drive-root checks.

Global resources continue through the protected global access route and require
an active subject entitlement. The configured Global Resources folder remains
separate from the course Library root.

Course files stored in separate subfolders must currently remain descendants of
the existing `M4L_GOOGLE_DRIVE_ROOT_FOLDER_ID`. Per-course independent Drive-root
configuration is not introduced in V102.8.

## Endpoints

| Endpoint | Purpose |
| --- | --- |
| `/api/library/catalogue` | Return the authorised course/global catalogue and source selector |
| `/api/library/course-resource/access` | Issue protected access for a resource in another authorised course |
| `/api/account/global-workspace` | Open the Library-only workspace for a global-only subscriber |

Existing `/api/account/switch-context`, course workspace and global-resource
access endpoints remain authoritative for their respective operations.

## Data and deployment boundary

- Platform schema remains `102.0.4`.
- No Platform or course Sheet tab/header is added.
- Account migration must not be rerun.
- No Worker variable, secret, binding or Apps Script deployment is added.
- No billing, payment, expiry or subscription-limit logic is added.
- Timetable behaviour and authority are unchanged.
- Current session persistence is unchanged; the approved future authentication
  policy remains in `docs/V102-AUTHENTICATION-SESSION-POLICY.md`.
- Production V101.1 remains untouched pending a separate production merge plan.
