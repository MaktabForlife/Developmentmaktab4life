# V102.7 protected Global Resources Google Drive

V102.7 makes `GlobalResources` operational with a designated private Google
Drive folder and removes manual URL entry for new global resources.

## Central folder configuration

The Platform Sheet stores one configuration record:

| PlatformConfig field | Value |
| --- | --- |
| `ConfigKey` | `GlobalResourceDriveRootFolderID` |
| `ConfigValue` | Google Drive folder ID |
| audit columns | Save timestamp, AccountID and display name |

Only a centrally authenticated `GLOBAL_ADMIN` can set or change this value. An
ordinary course `ADMIN` may browse the configured folder and manage global
resources but cannot change the root. Other roles cannot use Global Curriculum
management.

The setting is not a new schema field. `PlatformConfig!B3` therefore remains
`102.0.4`. A blank or absent setting does not fail Platform validation; the
validation response reports whether it is configured.

The root folder must remain private and be shared with the existing M4L Google
service account. Viewer permission is sufficient. V102.7 introduces no new
Cloudflare variable, secret or binding.

## Browse and resource creation flow

1. The authenticated Admin requests a folder listing.
2. The Worker reads `GlobalResourceDriveRootFolderID` from the Platform Sheet.
3. The requested folder is resolved through Google Drive metadata.
4. The Worker proves that it is the configured root or a descendant.
5. The UI displays folders and only selectable file types appropriate to the
   selected resource type.
6. On save, the Worker repeats the root and file-type validation.
7. The Worker rejects a file already referenced by another global resource.
8. `ResourceFormat` is derived from the Drive file.
9. `ResourceLink` receives the stable protected Worker route
   `/api/library/drive/file/<fileId>`.

The browser never accepts a submitted folder or file ID as authority. The
central account and role are revalidated first, and every Drive item is checked
against the configured root.

Legacy external HTTPS links already stored in `GlobalResources` remain readable
and editable. A new resource must select a Drive file. Replacing a legacy link
converts it to the protected route.

## Protected delivery

`POST /api/platform/global/resources/access` accepts a global `ResourceID` and
then verifies:

- a current central account session;
- active resource, subject and any referenced module/task;
- for non-ADMIN accounts, exactly one active `UserGlobalSubjectAccess` row for
  the resource's subject;
- a Drive-backed resource inside the current central root; and
- file compatibility with the stored resource type.

The response contains a short-lived signed URL for the existing private Drive
stream route. The stable `ResourceLink` by itself does not contain a usable
access token and does not expose the Google Drive file publicly.

ADMIN and GLOBAL_ADMIN bypass the learner subscription check for authorised
management/testing. They do not bypass folder containment or file validation.

## Global version and audit effects

The first folder configuration, a successful root change and each global
curriculum/resource mutation increment `GlobalCurriculumVersion`. Saving the
same root again is a no-op and does not increment it. Direct subscription
activation/deactivation still does not increment the curriculum version.

Root changes are audited as `SET_GLOBAL_RESOURCE_DRIVE_ROOT` or
`UPDATE_GLOBAL_RESOURCE_DRIVE_ROOT`. A root change is blocked if any existing
Drive-backed global resource is not contained in the proposed new root.

## Release boundaries

V102.7 does not:

- merge global resources into the current learner Library catalogue;
- create a standalone global-subject workspace;
- upload, move, rename or delete Google Drive files;
- add billing, payment, expiry or renewal rules;
- modify course Library folder configuration;
- change the approved but deferred browser-session authentication policy; or
- change production, which remains stable at V101.1.

Follow the repository-root `UPDATE-TODO.md` for exact deployment cells,
verification and non-destructive rollback.
