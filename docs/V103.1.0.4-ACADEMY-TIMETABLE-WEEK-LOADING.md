# V103.1.0.4 — Academy timetable week loading

## Purpose

Reduce Academy Home timetable latency by replacing per-day network navigation with a rolling cached timetable range.

## Initial range

The Account UI requests:

```json
{
  "days": 7
}
```

with no `startDate` on the normal startup path. The Worker resolves the start date in `PlatformTimezone`, so the returned range is today through today + 6 days.

The API retains its old two-day default when `days` is omitted so other callers are not silently changed.

## Rendering

Every date from `viewStart` through `viewEnd` becomes an `.academy-day` card in the existing horizontal scroll-snap track.

- Desktop: two cards visible.
- Mobile: one card visible.
- Each card retains its own V103.1.0.2 vertical session scroll area.

The horizontal track therefore becomes the primary fast day navigator.

## Prefetch

A passive scroll listener checks the remaining horizontal distance. When the user is within approximately 1.25 viewport widths of the loaded end, the UI requests another seven-day block starting on the next unloaded date.

The new response is merged by stable session/calendar keys, the existing horizontal scroll position is restored, and the expanded result is cached.

## Previous-day boundary

The left chevron remains supported. If a requested previous day is not loaded, the preceding seven-day block is requested and prepended. The requested date is then scrolled into view.

## Local cache

Cache key:

`m4l_academy_timetable_v103_1_0_4_<AccountID>`

Rules:

- TTL: 12 hours.
- Must resolve to the same central AccountID.
- Must start on the current date in the saved Platform timezone.
- Must contain at least seven days.
- Cleared by existing logout/context cache cleanup.

A valid cache renders before the fresh Worker response. If refresh fails, the cached timetable stays visible with a saved-data message.

## Worker range handling

The endpoint accepts `days` from 1 to 14. Invalid/missing values use the compatibility default of 2.

For a range crossing timetable weeks, the Worker determines every Monday–Sunday timetable week intersecting the requested range. Each Program timetable is read once, then its recurring weekly sessions are materialised for each relevant week. Global dated sessions are filtered over the complete range.

Calendar events are generated for the exact requested `viewStart`–`viewEnd` dates.

## Non-goals

V103.1.0.4 does not change:

- central identity authority;
- Program membership rules;
- session publication;
- timetable editing;
- Global Curriculum administration;
- Reboot operational records;
- Sheet schema.
