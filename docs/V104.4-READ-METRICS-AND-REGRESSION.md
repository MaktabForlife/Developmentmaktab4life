# V104.4 — Google Sheets Read Metrics & Full Regression

## Purpose

V104.4 closes the V104 Google Sheets read-optimisation phase by making the V104.1/V104.2 batching and V104.3 request-level deduplication measurable and regression-safe.

It is built on the completed **V104.3** Development tree. It does not replace or remove the V104.3 request-scoped read context.

## Measured read budgets

Backend integration tests record the actual outbound Google Sheets **GET** requests and enforce these budgets:

| Path / scenario | Sheets API requests | Batch requests | Direct reads | Logical ranges |
| --- | ---: | ---: | ---: | ---: |
| Academy timetable — one published Program | 4 | 3 | 1 | 18 |
| Academy timetable — rolling 7-day load | 4 | 3 | 1 | 18 |
| Attendance report | 1 | 1 | 0 | 2 |
| Student Progress task list | 1 | 1 | 0 | 4 |
| Progress report | 1 | 1 | 0 | 4 |
| Progress detail | 1 | 1 | 0 | 4 |
| TeacherAssign timetable with configured Global Zoom | 2 | 1 | 1 | 5 |
| TeacherAssign timetable requiring tolerant legacy Zoom fallback | 3 | 1 | 2 | 6 |

The Academy request budget is intentionally counted at the Google HTTP-request level:

1. central `UserAccounts` credential revalidation;
2. one Platform `batchGet` containing the Academy Platform snapshot;
3. one Program profile/config `batchGet`;
4. one Program authoritative timetable-source `batchGet`.

The rolling seven-day test must retain the same four-request budget as the normal Academy fixture. Loading more timetable days in Worker memory must not multiply Google API requests.

## V104.3 request-level deduplication remains active

V104.4 keeps the V104.3 request-local read context. The dedicated regression continues to verify:

- repeated exact reads issue one Google request per Worker request;
- concurrent same-range readers share one in-flight request;
- single reads and batch reads reuse exact overlapping ranges;
- overlapping batches send only missing ranges;
- SpreadsheetID remains part of the cache boundary;
- Course environment wrappers inherit the same private request context;
- a new Worker request never inherits prior Sheet values;
- returned rows are defensive copies;
- successful writes invalidate only the affected spreadsheet's request cache.

There is still no module-level, isolate-level, TTL, KV, D1, Redis or other cross-request Sheet-data cache.

## Source-level read-path guardrail

The V104.4 audit records the current operational read inventory:

- **23** `readGoogleSheetValues()` call sites;
- across **17** source files;
- **15** `batchReadGoogleSheetValues()` call sites.

The audit fails if direct-read call sites/files increase above that boundary or batch-read usage falls below the current boundary. Reductions are allowed.

This inventory is a regression guardrail, not a claim that every remaining direct read is defective. Some are deliberately single-range, tolerant or compatibility reads and are still protected by V104.3 request-level deduplication when repeated in the same request.

## Test-only metrics

`backend/tests/helpers/sheets-read-metrics.mjs` classifies mocked Google Sheets GETs by spreadsheet, batch/direct request and logical-range count.

These counters exist only in tests. V104.4 does not add read counts, internal diagnostics or Google request information to normal API responses.

## Full regression command

V104.4 adds one canonical backend command:

```bash
cd backend
npm test
```

`backend/tests/run-all.mjs` executes every backend `*.test.mjs` file in an isolated Node process and reports the aggregate result. The final V104.4 tree contains **63 backend test files**.

## Transient Google failure policy

V104.4 aligns the generic Sheets read client with the agreed V104 failure policy:

- retry only transient `429`, `500`, `502`, `503`, `504` responses;
- **one retry maximum** after the original read attempt;
- bounded backoff/jitter remains in place;
- persistent failure remains an authoritative failure and is never interpreted as an empty table.

The Google Sheets client regression verifies that a persistent transient failure stops after exactly two attempts total.

## V104 completion boundary

With V104.4, the planned optimisation sequence is complete:

- V104.1 — Platform batch reads;
- V104.2 — Program batch reads;
- V104.3 — request-level read deduplication;
- V104.4 — metrics and full regression gate.

No persistent cache is required by V104. The next roadmap stage may proceed to V105 Program Builder after Development deployment/acceptance of this final V104.4 tree.
