# V102.6 global curriculum and subscription management

## Purpose

V102.6 makes the central global curriculum schema operational for authorised
administrators. It uses the verified V102.5 Platform schema without adding or
changing any Sheet header.

An authenticated central `ADMIN` or `GLOBAL_ADMIN` can manage:

- `GlobalSubjectList`;
- `GlobalModuleList`;
- `GlobalTaskList`;
- `GlobalResources`;
- `UserGlobalSubjectAccess`.

`SENIOR`, `TEACHER`, `STUDENT`, legacy-only sessions and unauthenticated
requests are rejected by the Worker. A visible Admin URL or submitted ID does
not grant central management authority.

## Admin interface

Open:

```text
Admin Home → Global Curriculum
```

The screen contains five sections:

1. Subjects
2. Modules
3. Tasks
4. Resources
5. Subscriptions

Every global record displays within a clearly labelled `GLOBAL` platform
screen. Records are never hard-deleted. They are activated or deactivated.

## Curriculum rules

- Only the subject owns the global designation; all modules, tasks and
  resources in these central tabs inherit global scope.
- A module must reference an existing global subject.
- A task must reference an existing global subject and, when provided, a module
  belonging to that subject.
- A resource must reference an existing global subject and matching optional
  module/task branch.
- Supported resource types remain `EBOOK`, `PRINTABLE`, `AUDIO`, `VIDEO` and
  `OTHER`.
- Global resource links must be complete HTTPS links.
- Names are duplicate-checked within their relevant curriculum branch.
- IDs use namespaced UUIDs; no Sheet ID counter is introduced.

Moving a module or task to a different branch is blocked when dependent
records would be made inconsistent. Deactivation remains available and returns
dependency counts rather than deleting referenced records.

## Direct global-subject access

The Subscriptions section writes only `UserGlobalSubjectAccess`.

- It does not create a general `UserSubscriptions` table.
- It does not duplicate a Student course subscription from `UserCourseAccess`.
- It is unique by `AccountID + SubjectID`.
- Access may be activated only when both the account and global subject are
  active.
- Deactivation preserves the row and its audit history.

V102.6 stores and manages this entitlement but does not yet deliver the global
subject in the learner application.

## Audit and cache version

Every write appends a central `PlatformAuditLog` row containing:

- Audit ID and timestamp;
- account ID and name;
- authority (`ADMIN` or `GLOBAL_ADMIN`);
- the current CourseID for an ordinary course Admin;
- action, record type, record ID and changed fields.

Every subject, module, task or resource change increments
`PlatformConfig!B4` (`GlobalCurriculumVersion`). Direct access activation or
deactivation does not change the curriculum version because it changes who may
enter, not the curriculum content.

## No schema or environment migration

V102.6 requires:

- no Platform tab or header change;
- no course Sheet change;
- no account migration rerun;
- no Worker variable, secret or binding;
- no Apps Script deployment;
- no Google Drive folder change.

`PlatformConfig!B3` remains exactly `102.0.4`.

## Deferred

V102.6 does not implement:

- learner delivery of global subjects/resources;
- a global-subject-only account context;
- payment, billing, expiry or renewal handling;
- timetable or course-combination subscription checks;
- automatic central provisioning for newly registered course users;
- the approved authentication session-storage policy.

See `V102-AUTHENTICATION-SESSION-POLICY.md` for the separately approved login
change.

## Rollback

Roll back Worker and Pages to V102.5. Do not reverse the Platform schema and do
not delete any global curriculum, access or audit row created while V102.6 was
active. V102.5 validates those rows and safely ignores the V102.6 management UI.
