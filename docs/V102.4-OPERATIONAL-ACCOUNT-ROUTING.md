# V102.4 operational account routing

## Outcome

V102.4 connects the V102.3 unified account page to the existing operational
application. A migrated user now enters one PIN at `/account/<uniqueid>`, the
highest-authority context is selected, and a course context opens the matching
Admin or Student workspace automatically.

The existing Admin and Student pages are reused as operational shells. They do
not ask for a second PIN when launched by a valid central account session.

## Request trust boundary

The browser does not select a spreadsheet. For every course-scoped request, the
Worker performs this sequence:

1. Verify the signed central session and credential version.
2. Re-read the central account and confirm it is active.
3. Re-read the exact active course membership, role and CourseRecordID, unless
   the account is GLOBAL_ADMIN.
4. Resolve one active CourseRegistry row for the token's CourseID.
5. Set the request's Google Sheet target to that registered SpreadsheetID.
6. Resolve and validate the exact active local AdminRecords or StudentRecords
   row linked by CourseRecordID.
7. Run the existing endpoint authorization against that verified course user.

Any CourseID or role sent in a URL or request body is ignored for routing. A
missing, inactive, duplicated or mismatched record fails closed.

## Identity bridge

| Central context | Required course-local check | Operational workspace |
| --- | --- | --- |
| `ADMIN` | Exact active AdminID, UniqueID and ADMIN role | Admin |
| `SENIOR` | Exact active AdminID, UniqueID and SENIOR role | Admin |
| `TEACHER` | Exact active AdminID, UniqueID and TEACHER role | Admin, assigned-group restrictions retained |
| `STUDENT` | Exact active StudentID, UniqueID and class group | Student |
| `GLOBAL_ADMIN` in a course | Active registered course; no artificial local membership row | Unrestricted Admin |
| `GLOBAL_ADMIN` in Platform scope | No course data is available until a course is selected | Central context page |

GLOBAL_ADMIN is adapted to the legacy Admin authorization shape only inside a
validated course request. Its central AccountID remains the actor ID for audit
purposes.

## Navigation

- A course context opens automatically after successful login or session
  restoration.
- The context page includes **Open current course** as a recovery action if
  navigation is interrupted.
- The application Profile menu includes **Switch course or role**.
- Switching returns to `/account/<uniqueid>?switch=1`, keeps the verified
  account session, validates the chosen context centrally and issues a new
  scoped token.
- Logout clears both the operational and central session and returns to the
  personal account URL.

Direct `/admin/<uniqueid>` and `/student/<uniqueid>` logins remain active for
rollback. V102.4 does not redirect or retire those routes.

## Cache isolation

CourseID is included in shared application, timetable and progress cache keys.
When a context changes, course data caches are cleared before the next
workspace loads. The backend also returns `X-M4L-Course-ID` on dynamically
routed responses for development verification.

## Deployment requirements

- Start from the verified V102.3 source and completed central migration.
- Keep Platform schema version `102.0.3`.
- Keep the existing Worker variables and secrets unchanged.
- Deploy the Worker before Pages.
- Do not rerun the account migration.
- Apply only the V102.4 incremental update ZIP; another full repository upload
  is not required.

Use the root `UPDATE-TODO.md` for the exact installation and verification
sequence.

## Deliberately deferred

V102.4 is the secure operational routing cutover for already migrated users. It
does not complete the entire V102 programme:

- Course-local Admin/Student registration does not yet provision central
  UserAccounts and UserCourseAccess.
- Direct Google Sheets endpoints route by course, but per-course Drive-root and
  Apps Script URL configuration are not yet implemented. Libraries remain
  course-owned; do not activate a second production course's Drive/preview
  workflow yet.
- Complete confirmed Teacher write permissions for resources, tasks and
  progress still require a dedicated authorization release.
- Global curriculum merging, global cache-version invalidation and central
  dependency controls are not active yet.
- Cross-course teacher conflict indexing is not active yet.
- Published timetable snapshots are not yet expanded or used as the live read
  source; `TeacherAssign` remains live.
- Legacy role-specific login routes and `GOOGLE_SPREADSHEET_ID` remain until a
  later controlled retirement.
