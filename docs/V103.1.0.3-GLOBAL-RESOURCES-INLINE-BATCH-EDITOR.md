# V103.1.0.3 — Global Resources inline batch editor

## Purpose

Bring Global Resources administration into the same refreshed inline-editing model used by Global Subjects/Modules while preserving the protected Google Drive delivery model.

## UI model

The Resources tab contains:

- one screen-level Save action;
- filters for Resource Name, Global Subject, Type and Status;
- compact Resource summary rows;
- an inline editor directly beneath any opened Resource row;
- `+ Add a Global Resource` for unsaved draft rows;
- a separate Global Drive root configuration panel.

Dirty/new rows are visually highlighted. The Resources Save icon is larger and turns purple whenever any Resource has unsaved changes.

## Editable Resource fields

- protected Google Drive file;
- display/resource name;
- description;
- resource type;
- Global Subject;
- Module (optional);
- Task (optional);
- Active/Inactive status.

`ResourceFormat` remains derived from the selected Drive file and is displayed read-only.

## Batch endpoint

`POST /api/admin/platform/global/resources/save-batch`

Payload:

```json
{
  "globalCurriculumVersion": 12,
  "resources": [
    {
      "clientKey": "...",
      "resourceId": "...",
      "subjectId": "...",
      "moduleId": "...",
      "taskId": "...",
      "resourceName": "...",
      "resourceType": "EBOOK",
      "resourceDescription": "...",
      "fileId": "...",
      "active": true
    }
  ]
}
```

The endpoint validates the complete proposed final Resource collection before writing. If any row is invalid, none of the submitted Resource rows are written.

A successful dirty batch performs a single Google Sheets `values:batchUpdate`, increments `GlobalCurriculumVersion` once, and appends one PlatformAuditLog record per changed Resource.

The older single Resource endpoint remains for compatibility.

## Drive root safety

Changing `GlobalResourceDriveRootFolderID` remains separate from ordinary Resource edits. The operation does **not** move Google Drive files.

Before accepting a new root, the Worker resolves each persisted Drive-backed Resource file ID and verifies that the file is inside the proposed root or one of its descendants. A root change is rejected if any persisted Drive Resource falls outside that tree.

The UI also prevents the root operation while Resource drafts are dirty, preventing unsaved Resource changes from being lost during the root reload.

## Schema

No new Sheet/tab/header migration is required. `GlobalResources` keeps the existing schema and `PlatformConfig!B3` remains `102.0.8`.
